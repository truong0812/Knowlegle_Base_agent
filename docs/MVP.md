# MVP Design — Knowlegle Base Agent

Mục tiêu ngắn: xây prototype chuyển src đa-ngôn ngữ (Python, JS/TS, Java) thành Markdown có YAML front-matter + sidecar JSON, indexable cho QA.

## Kiến trúc MVP (tóm tắt)
1. Scanner → Language-Detector → Parser/Extractor (lang-specific) → Chunker (arch→module→class→method) → Summarizer (LLM) → MD-Generator + Sidecar → Indexer (FAISS) → QA endpoint.  
2. Orchestration: đơn giản bằng CrewAI workflow hoặc CLI chạy tuần tự/parallel.

## Data contract (sidecar JSON)
- Mỗi file/chunk xuất một sidecar JSON chứa provenance và metadata.

```json
{
  "id": "pkg.module.Class.method",
  "kind": "method",
  "language": "python",
  "path": "src/pkg/module.py",
  "signature": "def foo(bar: int) -> str",
  "summary": "Short summary",
  "tags": ["api","utility"],
  "source_commit": "abc123",
  "examples": ["foo(1)"],
  "tests": ["tests/test_module.py::test_foo"],
  "links": {"parent":"../modules/pkg.module.md"},
  "confidence": 0.88,
  "parse_evidence": [{"type":"ast","parser":"tree-sitter","ok":true}],
  "embedding_id": "emb_0001"
}
```

## MD front-matter example

```yaml
---
id: pkg.module.Class.method
kind: method
language: python
path: src/pkg/module.py
signature: "def foo(bar: int) -> str"
summary: "Short 1-2 sentence summary."
tags: [api, utility]
source_commit: abc123
tests: ["tests/test_module.py::test_foo"]
links:
  parent: ../modules/pkg.module.md
confidence: 0.88
---
```

Body: docstring (nếu có), detailed explanation, usage examples, call-graph snippet, related tests, security notes.

## CrewAI Task Message Schema (tối giản)
- Input/output đều là JSON sidecars; tasks read file contents when needed.

Example task payload (Parser/Extractor):

```json
{
  "file": "src/pkg/module.py",
  "language": "python",
  "content_path": "artifacts/files/src/pkg/module.py",
  "meta": {"repo":"repo-name","commit":"abc123"}
}
```

Extractor emits array of chunks (sidecar JSONs) to artifact store.

## Summarizer prompt template (sketch)
- System: "You are a code summarizer. Produce a concise summary, signature, examples, and risk flags."
- Input: chunk source, docstring, tests, call-graph neighbors.
- Output: JSON with fields: summary, examples, confidence, notes.

## Indexing
- Embeddings: batch sentence-transformers (all-MiniLM) for local MVP.
- Index: FAISS local; also store metadata in .kb/metadata/*.json for BM25-like filtering.

## CLI (MVP stubs)

```bash
# scan + detect languages
kb-agent scan --repo /path/to/repo --out .kb/artifacts

# run extractor pipeline (parallel)
kb-agent run --artifacts .kb/artifacts --out docs/kb
```

## MVP roadmap (milestones)
- M1: language-agent + scanner + file filtering (ignore generated) → produce sidecar list.
- M2: extractor for Python/JS/Java → produce chunks + YAML front-matter MD files.
- M3: summarizer integration (LLM stub) → fill summaries & examples.
- M4: local embeddings + FAISS index + simple QA HTTP endpoint.
- M5: CI integration: diff-based run and PR creator for docs/kb updates.

## Quality checks & heuristics
- Confidence scoring: parser success + docstring presence + test evidence.
- Flag low-confidence for manual triage.
- Exclude vendor/generated by patterns and manifests.

## Dev notes
- Start with a single-process Python prototype (no K8s). Use tree-sitter bindings and sentence-transformers.
- Cache LLM responses; batch summarization by module.
- Keep sidecar JSON as source-of-truth; MD rendering idempotent.

## Where to add code
- docs/kb/ generated artifacts
- .kb/artifacts/ raw files & intermediate sidecars
- .kb/metadata/ final metadata JSONs
- scripts/cli.py (CLI stubs)
